# AMRKB project instructions

Read README.md, AMRKB_Research_Protocol.md, AMRKB_Source_Editions.json and CHANGELOG.md.

- Agricultural Modes Reference Knowledge Base is an independent repository. Machine JSON owns structured records; the Scientific Register is generated by the local validator. The protocol owns methods; authored analytical prose, if separately approved, owns its own interpretations.
- Preserve all issued IDs, candidate scope, original terms, project status values, scientific uncertainty, memberships and relationships. Neutral display labels do not change canonical status meaning. Current ICAERUS labels retain two distinct candidate identities; archival spellings are evidence, not typographic errors to rewrite.
- Exact source editions are immutable in Archive. Raw quotations, pre-edit editions, the original README and development baselines are held in Development. Public evidence uses edition IDs, line locators and quotation fingerprints. Never replace archival editions, normalise quotes or silently repin hashes.
- No further research intake, bibliography completion, identity merge, scientific verification, schema redesign or harmonisation is authorised by editorial maintenance. Stage C visual review and owner acceptance remain pending.
- Run `python3 -B scripts/validate_amrkb.py` and `python3 -B -m unittest discover -s tests -v`. Full preservation verification requires explicitly supplied `--evidence-root` and `--development-root`; report unavailable checks honestly. Optional installed jsonschema validates the local schema. Never infer scientific truth, legal rights or reviewer authority from a pass.
- Edit the renderer deliberately for presentation changes; `--render-scientific` regenerates human output and is not an acceptance operation. Preserve GitHub duplicate-heading destinations. A future MkDocs importer must adapt its different duplicate suffix convention separately.
- DRM-MSP 0.1.0 review revision 2 is an unadopted candidate; Phase 4 documentary pilot closure is not full conformance or Phase 5 authority. Keep source, DRM, infrastructure and IRKB responsibilities independent.
- Work within this project. Do not modify siblings or the website, retrieve other histories, add a licence/DOI/release, stage, commit, configure remotes, push or publish without scoped authorisation. Git history is preserved; moving current files does not remove past content.
